# 角色与工作方式

你是一位资深全栈工程师（Next.js / TypeScript / LLM 应用），同时懂英语教学产品设计。请独立完成一个可本地运行的单用户 Web 应用，代号 **LexiLoop（词环）**。

一句话目标：把我在墨墨背单词里「已选入」的单词，变成可读、可听、可跟读的英语文章；文章里的生词一眼可见、点开有详情、一键加回墨墨。

工作方式：

1. 先给目录结构、数据模型、关键接口封装方案，我确认后再写代码。
2. 按里程碑交付，每个里程碑必须能跑、能验收。
3. 第三方接口以本文 §10 为准，不要重新猜；写入接口第一次调用前先打印请求与响应。
4. 不确定的产品语义，写进 README 的「假设」一节，不要默默替我做决定。
5. 这是单用户本地工具，不引入不必要的框架。

# 1. 背景与硬约束

- 墨墨背单词有官方开放 API，Base URL：`https://open.maimemo.com/open/api/v1`。
- Token 获取路径：墨墨 App → 我的 → 更多设置 → 实验功能 → 开放 API。个人 Token 存在服务端 `.env.local`，**永不写入仓库、永不下发前端**。
- 单用户、本地优先：`localhost` 运行，业务数据存本地 SQLite，音频存本地磁盘。
- 只调用官方 API。不逆向、不爬取、不模拟登录。
- 界面中文，文章英文。桌面优先，移动端 375px 可用。

# 2. 先对齐定义

| 术语 | 定义 | 判定方式 |
|---|---|---|
| 已选词库 | 墨墨账号里已加入学习计划的单词，当前 3754 个 | 按 §10.3 的时间窗算法全量同步，本地缓存 |
| 基础词 | 功能词 + **Oxford 3000**（含 CEFR A1–B2 核心词） | 本地词表 + ECDICT `oxford` 标记，**永不标注** |
| 生词 | 既不在已选词库、也不在基础词表中的实词 | lemma 查两张表 |
| 超纲词 | 生词中，超出当前难度带的词 | ECDICT 考试标签 |
| 新词数量 | 一篇文章里允许出现的生词个数 | 默认 12，可调 10–100，同时受 12% 密度上限约束 |
| 目标词 | 本次生成要复现的词，从已选词库采样 | 默认 12 个，按掌握度加权 |
| 补充要求 | 生成时额外输入的自然语言要求 | 单行文本框，≤300 字，软约束 |
| 影子跟读 | 播放一句 → 留白 → 我复述 | 不做录音，只做音频与留白 |

## 2.1 最重要的一条规则（用户明确要求）

**只要一个词在 Oxford 3000 里，即使它不在我的已选词库里，也不算生词，不标注。**

例如 `abandon`、`absorb` 属于 Oxford 3000，我没选它，也不标。
生词必须是「我不认识、且确实超纲」的词。判定顺序见 §5。

## 2.2 词形还原

**只做屈折还原，不做派生还原。**

- `running → run`、`went → go`、`better → good`：要还原。
- `happiness → happy`、`unhappiness → happy`：**不许**还原。

派生词是另一个词，还原过去会漏标。标注原文词形，卡片里显示原形。

# 3. 功能一：从词库生成文章

## 3.1 输入参数

| 参数 | 选项 | 默认 |
|---|---|---|
| 难度 | 高考 / 四级 / 六级 / 雅思 / 考研 / 托福 | 高考 |
| 篇幅 | 200 / 320 / 450 / 600 词 | **320（一篇高考阅读的长度）** |
| 新词数量 | 10–100 | **12** |
| 主题 | 随机，或手动输入 | 随机（避开最近 5 篇） |
| 体裁 | 记叙 / 说明 / 新闻 / 对话 / 议论 | 随机 |
| 目标词 | 自动采样 12 个，可「换一批」 | 自动 |
| 补充要求 | 自由文本，如「写一个关于城市夜班的护士的故事，多用对话」 | 空 |
| 音色 / 语速 | 男/女 × 美音/英音；0.75–1.15× | 女声美音，1.0× |

校验规则：新词数量不得超过「篇幅 × 12%」。320 词时上限约 38，UI 要显示「当前篇幅下最多约 N 个」。

## 3.2 生成流水线

1. **同步词库**：读本地缓存；超过 24 小时则后台刷新（全量约 34 次请求、70 秒，见 §10.3）。同步期间用旧数据，不阻塞生成。
2. **采样目标词**：从词库抽 12 个，权重：
   - `last_response` 为 `FORGET` / `VAGUE` 最高，`STICKING` 标签次之；
   - `study_count` 越低越高；
   - `last_study_date` 越久远越高；
   - 排除最近 3 篇用过的词。
3. **生成**：把「难度、篇幅、主题、体裁、目标词、新词数量、补充要求」交给 LLM，**不要把 3754 个词塞进 prompt**。允许集合 = 难度带 ∪ 已选词库 ∪ Oxford 3000，但只作为提示，真正的约束靠第 4 步校验。
4. **校验**（确定性代码，不许让 LLM 自检）：
   - 词数 320 ±15%
   - 句子 14–24，单句 ≤ 30 词
   - 生词数 ≤ 目标 + 3，且密度 ≤ 12%
   - 超纲词 ≤ 4（专有名词不计）
   - 目标词覆盖 ≥ 60%
   - 平均句长 ≤ 22 词
   - 无中文、无 Markdown、无括号注释
5. **修复**：只有以下情况才重写，最多 2 轮，把违规词清单回传：
   - 生词数超过「目标 + 3」
   - 超纲词 > 4
   - 目标词覆盖 < 60%
   不要因为 1–2 个词的偏差重写，地道优先。
6. **落库 + 异步 TTS**：文章先可读，音频逐句后台生成，SSE 推进度；前 3 句好了就能播。

## 3.3 输出 JSON Schema

```json
{
  "title": "string，不超过 8 个单词",
  "topic": "string",
  "genre": "narrative | expository | news | dialogue | argument",
  "sentences": [
    { "p": 1, "text": "The night shift begins long before the city sleeps." },
    { "p": 1, "text": "At the nurses' station, a kettle clicks off and someone laughs." }
  ],
  "targets_used": ["shift", "kettle"],
  "summary_zh": "一句话中文摘要，只用于历史列表"
}
```

## 3.4 约束

**硬约束**：无中文、无 Markdown、无单词表；不写脏话、暴力、色情、政治敏感、宗教争议；不编造具体数据/人名/机构名；标题不许「A Story About...」。

**软约束**：有场景、有细节、有具体动作；避免 AI 味的排比和空洞升华；目标词自然嵌入，不为用词造病句；补充要求优先服从，但不得违反硬约束。

**补充要求的处理**：作为 system prompt 里单独一段「用户附加要求」传入；超过 300 字截断；若与硬约束冲突，以硬约束为准，并在返回结果里标注「部分要求未采纳」。

## 3.5 失败与降级

| 情况 | 处理 |
|---|---|
| 词库为空/同步失败 | 用本地缓存；无缓存则进 Demo 模式 |
| 目标词不足 12 个 | 用现有数量，UI 标注 |
| 连续 2 轮不达标 | 接受 + 顶部徽标「含 N 个超纲词」+「再改一版」 |
| 单个 TTS 失败 | 该句标红可重试，不阻塞全文 |
| 墨墨 429 | 队列退避，UI 显示「同步中」 |

# 4. 功能二：分析我传入的文章

## 4.1 输入

粘贴文本 / 上传 `.txt` / `.md`，上限 20,000 字符。v1 不做 URL 抓取。

## 4.2 流程

1. 清洗：统一弯引号、去多余空行、修复断词连字符。
2. 分句：`Intl.Segmenter('en', { granularity: 'sentence' })`。
3. 分词：`Intl.Segmenter('en', { granularity: 'word' })`，保留 offset。
4. 还原：ECDICT `exchange` 构建的 lemma 表，OOV 走规则回退。
5. 分类：按 §5。
6. 统计：总词数、生词数、生词密度、Oxford 覆盖率、预计阅读时长。
7. 可选：复用 TTS 流水线生成跟读音频。

## 4.3 生词过多的处理

功能二无法控制生词量。侧栏按「是否在难度带内 + 词频」排序，默认显示前 30 个；提供 `全部 / 仅难度带内 / 仅高频` 筛选；支持「一键添加前 10 个」；密度 > 8% 时提示「这篇文章对你偏难」。

# 5. 标注规则（命中即停）

| 优先级 | 条件 | 处理 | 颜色 |
|---|---|---|---|
| 1 | 非单词（标点、数字、URL、邮箱、代码、emoji） | 跳过 | 无 |
| 2 | 句中首字母大写且非句首（疑似专名） | 跳过 | 无 |
| 3 | **命中 Oxford 3000 / 基础词表** | **跳过，即使不在词库** | 无 |
| 4 | lemma 在已选词库 | 跳过；`FORGET/VAGUE` 可加虚线下划线（默认关） | 无 |
| 5 | 不在词库、不在基础表、且在难度带内 | **生词**，可点击、可添加 | 琥珀色 + 点状下划线 |
| 6 | 不在词库、不在基础表、且超出难度带 | **超纲词**，可点击、默认收进侧栏 | 灰蓝色 + 点状下划线 |
| 7 | 同一 lemma 第 2 次及以后 | 同色，透明度 60% | 同上 |

```ts
type TokenStatus = 'ignored' | 'proper' | 'basic' | 'known' | 'new' | 'out_of_band'

function classify(token: Token, ctx: Ctx): TokenStatus {
  if (!token.isWordLike) return 'ignored'
  if (isUrlOrNumberOrCode(token)) return 'ignored'
  if (isProperNoun(token, ctx.sentence)) return 'proper'
  const lemma = lemmatize(token.normalized)
  if (ctx.basic.has(lemma)) return 'basic'      // Oxford 3000 优先
  if (ctx.vocab.has(lemma)) return 'known'
  return ctx.band.has(lemma) ? 'new' : 'out_of_band'
}
```

## 5.1 边界情况

- 句首大写：`The → the`；`I` 属基础词。
- 所有格：`world's → world`；`students' → student`。
- 缩写：`don't → do`，`it's → it`，`I'm → I`。
- 连字符：整体查一次，查不到再拆。
- 英美拼写：`colour/color` 同一 lemma。
- 不规则动词：`went/gone/going → go`。
- 比较级：`better/best → good`。
- `May`（月份）vs `may`（情态动词），拿不准按基础词跳过。

## 5.2 基础词表怎么来

三份本地数据：

1. `data/basic/function-words.txt`：约 200 个功能词与助动词。
2. `data/basic/oxford-3000.txt`：Oxford 3000 词表（含 CEFR 等级标注），**这是生词判定的核心**。
3. `data/basic/proper-nouns.txt`：可选人名/地名小表。

同时用 ECDICT 的 `oxford` 字段做交叉校验：命中任一即视为基础词。设置项提供 `Oxford 3000 / 仅 A1–B2 / 关闭`，默认 `Oxford 3000`。

# 6. 阅读器与单词卡

## 6.1 阅读区

- 衬线字体（Source Serif 4 / Lora），18–20px，行高 1.8，最大宽度 68ch，米色背景，深色模式。
- 句子是播放单元：hover 出播放键，当前句浅色高亮并自动滚动。
- 顶部：难度、词数、生词数、预计时长、重新生成、导出。
- 快捷键：`空格` 播放/暂停，`←/→` 上一句/下一句，`R` 重播。

## 6.2 单词卡

桌面 Popover 锚定，移动端底部 Drawer；缓存命中 300ms 内出内容。

内容与数据源（**顺序不能错**）：

1. 单词、音标、发音按钮（TTS 生成并缓存）。
2. 词性 + 中文释义、英文释义：**ECDICT 主源**。
3. 考试标签（CET4/CET6/IELTS/TOEFL）、牛津/柯林斯标记：ECDICT。
4. 词形信息（running / 原形 run）：ECDICT `exchange`。
5. 本文原句：文章数据。
6. 例句：ECDICT 无例句时用 LLM 生成 1–2 条，必须标「AI 生成」。
7. 墨墨个人笔记/例句/释义：只有你自己创建过才显示，接口返回空就不显示。
8. 操作：`加入墨墨学习` / `已在词库 ✓` / `忽略`。

**不要写「墨墨词典优先」**：墨墨接口只返回 `{id, spelling}`，没有释义。

## 6.3 添加闭环

- 点击 → `POST /memo/study/add_words`，body `{ words: [{id}], advance: false }`。
- 返回 `{ added_count }`：1 表示成功，0 表示已在学习计划或已达上限，UI 要如实提示。
- 先 `POST /memo/vocabulary/query` 用拼写换 `voc_id`（≤1000 个/次），缓存映射。
- 幂等：本地记录 `lemma → voc_id + added`，重复点击不重复请求。
- 三态：`pending / synced / failed`，设置页可重试。

# 7. 影子跟读音频

## 7.1 生成策略

**逐句合成，不做整篇强制对齐。**

- 每句一个音频：`{ index, text, url, durationMs }`。
- 客户端 `HTMLAudioElement` 按句序列播放，句间插静音。
- 好处：句级同步天然成立、单句重播、留白可调、不需要 ffmpeg、不需要 WhisperX。
- 代价：句间韵律略断；用 ElevenLabs `previous_text/next_text` 或 Azure SSML 缓解。
- 缓存键：`hash(text + voice + provider + model)`。

## 7.2 两种模式

| 模式 | 行为 | 用途 |
|---|---|---|
| 连读版 | 句间 300ms | 泛听、通读 |
| 跟读版 | 句后留白 = 句长 × 系数（0.8 / 1.2 / 1.6） | 影子跟读 |

## 7.3 播放器

- 播放/暂停、上一句/下一句、单句循环（1/3/5 次）、整篇循环、按句进度条。
- 变速 0.75 / 0.9 / 1.0 / 1.15，`audio.preservesPitch = true`，不重新合成。
- 句间留白可调。
- **不做录音、不做发音评分。**

## 7.4 TTS Provider

```ts
interface TtsProvider {
  id: 'azure' | 'elevenlabs' | 'openai'
  synthesize(text: string, opts: VoiceOptions): Promise<{ audio: Buffer; durationMs?: number }>
}
```

默认 Azure Speech（稳定、便宜、国内可达），ElevenLabs 可选，OpenAI 兜底。不要写死一家。

# 10. 墨墨 API 集成（已实测，照此实现）

## 10.1 基本信息

- Base：`https://open.maimemo.com/open/api/v1`
- Header：`Authorization: Bearer <token>`
- 响应统一包裹：`{ "success": true, "data": {...}, "errors": [] }`，取数据用 `json.data`。

## 10.3 全量同步算法（已验证：3754 词，0 缺失，34 次请求）

接口**没有 offset 分页**，只能按 `next_study_date` 时间窗切片：

```ts
async function syncAll() {
  const all = new Map()
  const queue: [Date, Date][] = [[MIN, MAX]]
  while (queue.length) {
    const [s, e] = queue.shift()!
    const count = await countWindow(s, e)          // as_count: true
    if (count === 0) continue
    if (count > 1000) {                            // 窗口太宽，二分
      const mid = new Date((+s + +e) / 2)
      queue.push([s, mid], [mid, e])
      continue
    }
    const records = await fetchWindow(s, e)        // limit: 1000
    records.forEach(r => all.set(r.voc_id, r))
  }
  return [...all.values()]
}
```

要求：

- 请求间隔 ≥2s；全量约 70 秒，必须放后台任务 + SSE 进度，不能阻塞页面。
- 结果写 `vocab` 表；24 小时 TTL；同步期间继续用旧数据。
- 记录字段：`voc_id`、`voc_spelling`、`add_date`、`first_study_date`、`last_study_date`、`next_study_date`、`last_response`、`study_count`、`tags`。
- `last_response` 枚举：`FAMILIAR` / `VAGUE` / `FORGET` / `WELL_FAMILIAR` / `CANCEL_WELL_FAMILIAR` / `STUDY_RESPONSE_UNSPECIFIED`。
- 实测分布（2026-10）：STICKING 460、FORGET 166、VAGUE 37、FAMILIAR 3523，可作为采样权重参考。

## 10.4 加词

```http
POST /memo/study/add_words
{ "words": [{ "id": "voc-..." }], "advance": false }
→ { "added_count": 1 }
```

- `id` 通过 `/memo/vocabulary/query` 用拼写换，批量 ≤1000。
- `added_count` 可能小于请求数：已在学习计划或达到单词上限。
- `advance: true` 会一并提前复习，需要 10 级，默认 false。
- 第一次调用写入接口时，先打印完整请求/响应到日志（脱敏），确认无误再接入 UI。

## 10.5 不能做的事

- **墨墨不提供词典释义**：`/memo/vocabulary` 只返回 id + spelling；`interpretations/phrases/notes` 是用户自建内容，通常为空。释义、音标、例句必须走 ECDICT / LLM。
- 不提供单词发音音频，用 TTS 生成并缓存。
- 不提供「已选词书」元数据，只有学习记录。

## 10.6 安全

- Token 存 `.env.local`（`MAIMEMO_API_TOKEN`），只读服务端；前端接口不返回。
- `.gitignore` 覆盖 `.env*`、`data/`。
- 日志脱敏：不打印 Token 和完整响应体。
- 所有响应先 Zod 校验再入库。

# 11. 非功能要求

- 首屏 < 1.5s；320 词生成 P95 < 25s；首句音频 < 5s；全量同步后台完成。
- 无 Token 时进入 Demo 模式：内置 300 词示例词库 + 3 篇预置文章 + 预生成音频。
- 断网后已生成文章仍可读、可听。
- 移动端 375px 可用；颜色不是唯一标识（生词有点状下划线）；支持键盘与 aria。
- 单测覆盖：分词、lemma、分类、校验器、时间窗切分；E2E：生成→标注→点词→加词。
- 任何 API 失败都要有中文提示 + 重试入口，不允许白屏。

# 12. 验收标准

1. 一段只含 `a/an/the/it/is/of/to` 的文字，标注数为 **0**。
2. Oxford 3000 里的词（如 `abandon`）即使不在词库，也**不标注**。
3. 全量同步得到 3754 条左右记录，`missing = 0`；中断后能续传。
4. 生成 320 词高考难度文章：生词 12±3，密度 ≤12%，超纲 ≤4，目标词覆盖 ≥60%。
5. 点击生词，缓存命中 300ms 内出卡：音标、释义、标签、原句。
6. 点「加入墨墨学习」返回 `added_count=1`；重新分析同篇，该词变「已知」。
7. 跟读模式留白可调，单句可循环 3 次，变速不改音高。
8. 刷新后文章、标注、音频仍在；断网可读可听。
9. 连续生成 5 篇，主题不重复，标题不模板化。
10. 墨墨接口挂掉时给出明确提示，Demo 模式可完整体验。
